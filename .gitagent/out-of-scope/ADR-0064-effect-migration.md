# ADR-0064: Migrate OpenGantry to Effect — Effect Schema replaces zod, core depends on effect, no new network path

**Status: ACTIVE** (issue [#400](https://github.com/jeger-ai/opengantry/issues/400); owner sign-off 2026-11-25, re-decisions the same day; recorded in MSN-0410, slice S1.1). This record carries the decisions. The work ships in five phases, one Planner mission per slice; phases 1 and 2 ship as one release.

## Context

Issue #400 asks to move OpenGantry to [Effect](https://effect.website): typed errors, scoped lifetimes for processes, sockets, temp directories and locks, services with live and test layers, and one schema library. Measured on 2026-11-25 (`scripts/effect-inventory.sh`): 26 sync spawn calls in 16 production files, 8 async spawn calls, 177 `readFileSync`/`writeFileSync` calls in 84 files, 14 zod importers, 16 commander importers, 14 hand-written `Error` classes and 37 `Date.now`/`setTimeout` calls.

`effect` 4.1.5 has no dependencies. Platform, CLI and schema live inside it (`effect/process`, `effect/cli`, `effect/schema`); the v3 packages `@effect/platform` and `@effect/cli` are not used. It also ships network modules (`effect/http`, `effect/net`, `effect/rpc`, …). `@effect/platform-node-shared` 4.1.5 provides the Node layers and depends on `ws` and `@types/ws`; its barrel (`dist/index.js`) re-exports `NodeWS` (`export * from "ws"`), `NodeDns`, `NodeDatagramSocket` and `NodeAddressResolver`, and `NodeSocketServer.js` statically imports `NodeWS.js`. `@effect/platform-node` requires redis as a peer dependency and brings undici.

## Decision

### Owner answers (2026-11-25)

| Point | Decision |
|---|---|
| P1 Ambition | Full migration: every package and the CLI. |
| P2 Schema | Replace zod with Effect Schema. |
| P3 Core | Core depends on `effect` (amends ADR-0054). |
| P4 Surface | Effect inside the bundles; the public API stays Promise-based or sync (4.x, no break). |
| P5 CLI | `effect/cli` replaces commander. |
| P6 Budgets | Net ≤ 0 production lines per phase; ratchet `ARCH_BASELINE.json` after each phase. |
| P7 JSON Schema | Same verdicts; the generated bytes may change once (CHANGELOG). Canonical JSON, digests and signatures stay byte-identical. |
| P8 Platform | Superseded by P8′. |

### Re-decisions (2026-11-25)

- **P2″** No zod exception. `mcp-tools-register.ts` keeps one Effect Schema per tool, generates its JSON Schema, and registers tools through the MCP SDK's low-level `Server` (`ListTools`/`CallTool` handlers). zod stays only as a transitive dependency of `@modelcontextprotocol/sdk`: no registry row, no importer.
- **P4′** `verifyInput` becomes an Effect Schema. The inferred `VerifyInput` type is unchanged. This is the only allowed change to the public type surface; CHANGELOG notes it.
- **P6′** Phases 1 and 2 ship as one release, and net ≤ 0 is judged over their sum. A layer named in the legislated mission may rise (`gantry arch check --ratchet --allow-raise`) while the sum over all layers stays ≤ 0. `scripts/arch-net-sum.mjs <base-ref>` measures it.
- **P8′** The live layers come from `@effect/platform-node-shared` only. `@effect/platform-node` is not used.

### Amendments

- **ADR-0052 A6:** "one schema library, zod" becomes "one schema library, Effect Schema", with JSON Schema generated from it. zod is removed from `package.json` and the registry when its last importer goes (phase 2).
- **ADR-0052 B7:** "one schema library" now means Effect Schema; core's runtime dependencies follow ADR-0054 as amended below.
- **ADR-0054 decision 1:** core depends on `effect` and `yaml`, nothing else, and stays I/O-free. Core may import the pure `effect` modules. It may not import `effect/process`, `effect/socket`, `effect/cli`, `effect/FileSystem` or `effect/Path`, nor name `FileSystem`, `Path`, `ChildProcess` or `ChildProcessSpawner` in an import from `"effect"`.

### Network: ADR-0055 upheld

Effect adds no network path. ADR-0052's non-goal and ADR-0055's single opt-in exception (keyless signing through `sigstore`) stand. The existing network paths are unchanged: policy pull and deps fetch (`node:https`, `node:tls`, `fetch`), the GitHub host broker, the architecture fetch and the sandbox probe.

**Allowed subpaths of `@effect/platform-node-shared`:** `NodeFileSystem`, `NodePath`, `NodeChildProcessSpawner`, `NodeSocket`, `NodeRuntime`, `NodeStdio`, `NodeTerminal`. None of them imports `ws`, `effect/net` or an HTTP module (checked in the 4.1.5 `dist/`; `NodeSocket` uses `node:net` and `node:tls` for local sockets). Only `packages/git/src/platform.ts` may import them.

**Banned modules**, in every production file:
- `ws`, `undici` and `@effect/platform-node`, each with any subpath;
- the bare `@effect/platform-node-shared` (the barrel) and every subpath outside the allowlist: `NodeWS`, `NodeSocketServer`, `NodeDatagramSocket`, `NodeAddressResolver`, `NodeDns`, `NodeClusterSocket`, `NodeHttpCompression`, `NodeCrypto`, `NodeSink`, `NodeStream` and any later addition;
- `effect/{ai,chat,cluster,devtools,eventlog,http,http-api,net,persistence,rpc,sql,workflow,workers,graphql,observability}`, each with any subpath.

**Enforcement** in `TARGET_ARCHITECTURE.yaml`, judged over the whole tree by `gantry arch check`:
- `RULE-NET-EFFECT` bans the modules above in static `from`, side-effect `import "…"`, dynamic `import(…)` and `require(…)`;
- `RULE-CORE-EFFECT-PURE` bans Effect's I/O modules in `packages/core/src/**`;
- `OWNER-EFFECT-PLATFORM` makes `packages/git/src/platform.ts` the only importer of `@effect/platform-node-shared`.

The rules are regex pattern and owner rules, because import rules match a specifier substring only. They judge direct imports. A member reached through a namespace (`E.FileSystem` after `import * as E from "effect"`) and transitive reach are not seen by them; the esbuild metafile check of both bundles (S1.2) covers transitive reach.

### Dependencies and the reviewed lockfile graph

`effect` and `@effect/platform-node-shared` are runtime dependencies, `ajv` a dev dependency (JSON Schema verdict checks in phase 2, draft 2020-12). All three are pinned exactly and registered in `.gitagent/registry/dependencies.yaml`.

ADR-0062 dependency admission is not active in this repository (no `verify.yaml` dependency policy, no approvals folder), so the reviewed graph is recorded here. `npm install` (npm 11.19.1) changed `package-lock.json` as follows:

| Package | Version | Change |
|---|---|---|
| `effect` | 4.1.5 | added (direct, runtime; no dependencies) |
| `@effect/platform-node-shared` | 4.1.5 | added (direct, runtime; peer `effect ^4.1.5`) |
| `ws` | 8.23.0 | added (through platform-node-shared; optional peers `bufferutil`, `utf-8-validate` not installed) |
| `@types/ws` | 8.18.2 | added (through platform-node-shared) |
| `ajv` | 8.20.0 | already in the graph through `@modelcontextprotocol/sdk`; now also a direct dev dependency, no new node |
| `@types/node` | 24.19.2 | no longer dev-only: `@types/ws` depends on it |
| `undici-types` | 7.24.6 | no longer dev-only: `@types/node` depends on it (type declarations only; not `undici`) |

No other lockfile entry changed. A later version or a new transitive package is a new decision.

### Conventions

- A service is `XService` (the tag), its live layer `XLive`, its test layer `XTest`. Test layers live in `packages/*/src/testing/`.
- Refusals are `Data.TaggedError` families that carry today's `code` and `exit`.
- `Effect.runSync` and `Effect.runPromise` appear only at entries and in `packages/core/src/run-bridge.ts`, which rethrows the original failure. An old sync or Promise export stays a run-bridge wrapper until its last caller is ported.

### Budgets

Cold start and bundle size budgets: measured in S1.2, signed by the owner before S1.2b.

## Consequences

- Adopters install `effect`, `@effect/platform-node-shared`, `ws`, `@types/ws`, `@types/node` and `undici-types` with the main package. None of the network modules is reachable from an entry.
- Wire formats, digests, signatures, exit and error codes and the existing conformance goldens do not change. Goldens are only added: argv errors before commander goes (S1.5), help text in phase 5.
- Two styles live side by side until phase 5 ends; `scripts/effect-inventory.sh` tracks what is left.
- **Risk.** A typed error can turn a refusal into a recoverable branch. Phase 1 adds a lint rule against the combinators that drop a failure (S1.3).
